# 復旧（オーナー）

[English](RECOVERY.md) | [繁體中文](RECOVERY.zh-Hant.md) | [日本語](RECOVERY.ja.md)

このドキュメントは、オーナーがサインインできなくなったときにできること・できないことを説明します。

## 結論：パスワードはオフラインでリセットできません

オーナーのパスワードは `HMAC-SHA256-KEYED-V1` で保存されます。ランダムなソルトと、Worker のルートシークレット（`JWT_SECRET`）から導出された専用の鍵を組み合わせたものです。Cloudflare は Worker のシークレットの値を誰にも返さないため、**R2 へのアクセスだけを持つツールでは、Worker が受け入れるパスワードのレコードを書き出せません。**

したがって：

- `node scripts/reset-owner-password.mjs` は**この事実を説明してエラーで終了するだけです**。R2 の読み取りも書き込みも行いません。
- これは意図的な仕様で、欠陥ではありません。偽の成功を報告することはなく、公開の「パスワードを忘れた」入口や恒久的なバックドアも追加しません。初回セットアップ時には Worker がオーナーのパスワードを自分で生成します（非公開の R2 オブジェクト `auth/initial-owner-password.txt`）。このパスワードも復旧には使えません。
- オフラインでリセットするために `JWT_SECRET` をバックアップしたり貼り付けたりする必要はなく、してはいけません。

## 日常の方法：サインイン後にパスワードを変更する

サインイン済みのオーナーは **Security settings → Change password** でパスワードを変更できます（直近の再入力が必要です）。変更すると、他のサインイン中のセッションはすべて終了します。

サイトには**互いに独立した**3つのサインイン方法があります：パスワード、認証アプリ（TOTP）、パスキーです。どれか1つだけでサインインできます（認証コードは**第二要素ではありません**）。1つでも使えれば、サインインして Security settings でほかを管理できます。予備として、もう1つの方法を登録しておくことをおすすめします。

## どのサインイン方法も使えないとき

現時点では安全なオフライン・リセットの手段はありません。デプロイ担当者は次の選択肢を検討できます：

1. まず一時的な問題でないか確認します。パスキーが元のドメインで使われているか、認証アプリの時刻が正しいか、サインインがロックされていないか（ロックの解除を待つ）。
2. オーナーのレコードが壊れて復旧できず、**オーナーを消去することを承諾する**場合：デプロイ担当者が自分の Cloudflare 認証情報で `auth/owner.json` と `auth/bootstrap-marker` を削除し、`SETUP_ARMED` が引き続き `yes` であることを確認します。次にサイトを開くと、オーナーが作り直されます。`auth/initial-owner-password.txt` が残っていればそのパスワードを使い、なければ新しいものを生成して同じオブジェクトに保存します。これにより、すべてのオーナーのセッションと、紐づけられた認証アプリやパスキーは無効になります。`codes/`、`sessions/`、ファイルのデータは変わりません。これは破壊的な操作です。先に `auth/owner.json` をバックアップし、メンテナンス時間帯に行ってください。
3. `JWT_SECRET` を変更または紛失した場合：パスワードや認証アプリはもう検証できません。手順は2と同じです。発行済みのアップロード・ダウンロードのトークンも使えなくなります。

## 初回セットアップが中断された（マーカーはあるがオーナーがない）

初回セットアップでは、Worker がパスワードを準備し、`auth/bootstrap-marker` を確保してから、`auth/owner.json` を書き込みます。マーカーは書けたのにオーナーの書き込みに失敗すると、サイトはオフラインでの復旧を求めます。デプロイ担当者用のツールで**マーカーだけを削除**し、初回セットアップをもう一度実行できるようにします：

```bash
npx wrangler login
node scripts/recover-bootstrap.mjs --bucket pocket-chest
```

- マーカーがあり、オーナーがない場合にだけ動作します。オーナーがあれば拒否し、マーカーはそのまま残ります。
- このツールは**オーナーを作成せず、パスワードも不要です**。実行後の初回セットアップは Worker が行います（`SETUP_ARMED` が必要で、これはデプロイ担当者が設定します）。
- 匿名の HTTP 経路で再セットアップすることはできません。`wrangler r2 object delete` は条件付き削除ではないため、メンテナンス時間帯に、公開のサインインを止めた状態で実行してください。
- それ以外の状況で手作業でマーカーを削除しないでください。オーナーが存在する場合は、絶対にマーカーを削除しないでください。

## このドキュメントの範囲外

- Cloudflare アカウントの設定の変更、R2 バケットの作成や削除。
- 公開の「パスワードを忘れた」HTTP API。そのようなものはありません。

## テスト

- `test/recovery-cli.spec.ts`：オフラインでのリセットは拒否され、何も読み書きされず、既存のオーナーとパスワードはそのまま残ります。
- `test/bootstrap-recovery.spec.ts`：中断した初回セットアップはマーカーを削除するだけです。オーナーが存在する場合、マーカーがない場合、削除中にオーナーが現れた場合は、拒否されるか報告されます。
- 本番環境では、オーナーのレコードを変更するテストを自動実行してはいけません。完全な手動のリハーサルは、隔離された R2 バケットで行います。
